# Red flags — audit of 19 October 2026

Scope: the kernel/module split and the first real-estate workflow (ADR-0022, ADR-0028, ADR-0029,
ADR-0030; commits `6ed7c77..6073832`), read against the code at `6073832`. Every code finding
below was reproduced (a test, a script, or a request against production where it was read-only).
Each flag has an id; its fix references it, and the **Status** column is kept current.

## Architecture

| Id | Flag | Why it matters | Fix | Status |
|---|---|---|---|---|
| A1 | "Workflow" means two engines: runbooks run through the governed loop; case workflows (`parse → compute → check`, ADR-0030) run beside it in `app/workflow_agents/service.py`. | Justified today (ADR-0030 D6: computing writes nothing outside the case). The risk is drift: the first case action that reaches the outside world (sending letters) being added as an endpoint instead of a governed run. | Make it structural: a module's code may import nothing that does I/O (no HTTP/browser/DB clients, no relative escape out of the module) — the boundary test (A1 → C10). Anything that acts outside a case is a runbook with `check` as its postcondition (ADR-0030 D6, unchanged). | open |
| A2 | Only conversational agents "compile". A conversational agent is published as an immutable snapshot; a workflow agent's settings are live and unversioned, and a computation did not record which settings it used. | The two agent categories are not equal: a workflow result could not be traced to the decisions it was computed under. | Every computation records the exact input and settings it used, with the rules version (C4). Publishing and pinning workflow-agent settings comes with the approval gate (ADR-0028 step 5), as ADR-0030 "Not building" says. | open |
| A3 | The kernel is not separable yet: the practice's code still lives in `app/workloads/conversational`, `app/sync`, `app/connectors`, and the `voice_agents` surface is a podiatry receptionist. | A second conversational vertical (e.g. real-estate lead calls) cannot reuse the voice surface until the conversation kit is extracted. | Planned, not a defect: ADR-0022 build plan steps 2c (conversation kit) and 3b (move praxis into `modules/praxis`). Do them before a second conversational module, not before. | tracked |
| A4 | Documentation drift: ADR-0022 says "proposed" while accepted ADR-0028 amends it and the code implements it; two ADRs are numbered 0011; CLAUDE.md §XIII calls `app/workloads/conversational/` a placeholder and lists three tiers where the Studio offers two kinds of agent. | A reader codes to a fiction (CLAUDE.md §0: "if the doc is stale, fix it"). | ADR-0022 → accepted (partly built); the second 0011 noted as such in the index; CLAUDE.md §XIII brought up to date. | fixed |
